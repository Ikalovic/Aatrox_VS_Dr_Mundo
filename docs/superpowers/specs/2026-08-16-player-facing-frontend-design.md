# 玩家三幕式前端设计

## 目标

把现有的开发调试式单页改为面向玩家的肉鸽界面。玩家不应看见原始 API 返回、JSON、批量购买 JSON 输入框或“挑战 Boss”调试按钮；一局游戏通过地图、战斗和事件三种场景自然推进。

## 场景与状态

页面由 `run.stage` 驱动，任何时刻只显示一个主场景：

1. **地图幕**：`event`、`cleared` 或刚创建对局时显示。渲染 12 层纵向路线；当前节点、已完成节点和本层可达节点有不同视觉状态。点击可达节点进入它。
2. **战斗幕**：`minion`、`monster`、`hero`、`boss` 显示。上方是敌方姓名、血条和护甲；下方是剑魔的状态、血条与 Q/W/E/R 四张招式卡。回合日志只显示命中、闪避、伤害和敌方已结算的招式，不显示后端 JSON。战斗结束自动回到地图幕；失败显示失败覆盖层和“重开一局”。
3. **事件幕**：`shop` 或 `campfire` 显示。商店以装备卡与属性锻造器卡展示；篝火先展示“休息 / 冥想”两个大选项，冥想后显示三张候选海克斯卡和刷新按钮。完成/关闭事件后返回地图幕。

顶栏始终显示本局金币、HP、攻击、护甲、刷新券，右侧有简短“本回合记录”抽屉。

## 玩家操作与保留的 CTF 入口

- 普通商店购买是单件卡片按钮；批量购买保留为一个不显眼的“采购清单”折叠面板，面向懂 API/源码的选手而不是默认玩家路径。
- 篝火冥想的三候选与刷新是默认交互。检索框不在初始 UI 显示；它可以作为“研究档案”折叠区，保持 SQLi 的预期攻击面但不破坏第一眼体验。
- 英雄奖励只在英雄战胜后，在地图幕/战斗胜利摘要显示“领取战利品”按钮。
- Flag 只在 Boss 被击败的胜利覆盖层显示。

## 视觉与可访问性

整体采用暗色峡谷石板、猩红剑魔强调色和金色奖励强调色；不依赖图片资源。信息使用文字和颜色双重区分，所有可操作元素是真实 `button`，移动端单列布局可用。术语和数值延续当前中文内容。

## 数据与实现边界

复用既有 API 与后端规则，不改变 SQLi、竞态、批购漏洞、伤害和地图生成。前端增加纯展示用场景状态、战斗记录格式化以及组件化渲染函数；不得把 Flag、契约判定或任何战斗结算迁移到浏览器。

## 验收

- 首屏与所有主场景不显示 JSON 原文或开发调试按钮。
- 创建一局后可从地图进入可达节点；战斗、篝火、商店随 `run.stage` 切换。
- Q/W/E/R、篝火休息/冥想/刷新/选择、单件购买及锻造器均可从玩家界面操作。
- 旧的 CTF API 链及 Docker 自动求解器仍能得到 Flag。
- HTML 结构测试、JavaScript 语法检查、pytest 和 Docker 端到端求解通过。

## 自检

- 无占位符或待定项。
- 三幕状态以现有 `run.stage` 为唯一来源，未与后端路由冲突。
- “折叠的采购清单/研究档案”明确保留漏洞入口，但默认不干扰玩家路径。
- 范围限于前端展示与交互编排；不修改题目后端机制。
