# SVG 连线地图与真实怪物血量设计

## 目标

让 25 层路线以类似《杀戮尖塔》的节点和连线可视化呈现，提升每层选择密度；同时修复前端以旧固定值显示动态怪物总血量的问题。

## 地图拓扑和节点密度

- 第 1 层和第 25 层各一个节点；第 2–24 层随机 4–6 个节点。
- 后端继续只生成下一层的局部连接，每个节点有 1–2 条向前边，禁止相邻层全连接；保证主链可达。
- 地图前端为每层节点分配相对横坐标，纵坐标按楼层；每条 `map.edges` 作为 SVG `<line>` 从源圆心画到目标圆心。
- 当前节点出发的边用高亮颜色；已离开/完成边和节点低饱和；可进入节点高亮；其他节点不可点击。
- 使用颜色、简短文字和圆形节点区分类型，不依赖图片资源。
- 桌面端在地图容器内垂直浏览；窄屏容器可横向滚动，SVG 与节点使用同一宽度坐标系统，连线不得错位。

## 敌方最大生命

- `runs` 新增 `enemy_max_hp INTEGER NOT NULL DEFAULT 0`。
- 进入普通、精英或英雄节点时，服务端将楼层计算出的动态 HP 同时写入 `enemy_hp` 和 `enemy_max_hp`。
- 每次游戏状态和战斗动作响应均带有 `run.enemy_max_hp`；Boss 使用既有 `boss_hp / 32000`。
- 前端非 Boss 敌人血条只使用 `enemy_hp / enemy_max_hp`，禁止使用本地固定最大 HP 常量。

## 重开与伤害浮字

- 前端提供独立的 `startNewRun()`；首屏、失败弹窗和胜利弹窗都调用它，不依赖已被场景重绘移除的 DOM 按钮。
- `startNewRun()` 调用 `POST /api/runs`，清空前一局地图、事件、锻造器和战斗浮字状态，随后拉取新地图并渲染地图幕。
- 每次战斗动作响应后，在敌方卡片叠加 `-${damage}` 红色浮字；若 `enemy_damage > 0`，在剑魔卡片叠加 `-${enemy_damage}` 橙红浮字；若本回合 HP 增加，在剑魔卡片叠加 `+{heal}` 绿色浮字。
- 浮字只使用后端响应前后 HP 的差值和响应 `damage`，1 秒内 CSS 动画淡出并从 DOM 删除；不参与任何数值计算。

## 玩家信息与友好反馈

- 页面所有默认可见文案使用中文玩家术语；不得展示 `stage`、`invalid_purchase`、稀有度内部键、JSON 或 API 路径。
- 顶栏除既有数值外显示“第 N 层 · 节点类型”；地图节点悬停/聚焦显示节点类型、战斗风险或主要收益，且 SVG 边清楚标示实际可走路线。
- 商店装备卡显示名称、价格、属性和购买条件。失败响应在前端映射为中文弹窗：金币不足、背包已满、装备规则冲突、尚未完成英雄战斗或当前不在商店；每条都包含一个可行动的简短建议。
- 篝火和事件卡显示选择的收益、代价、是否一次性；战斗记录使用中文叙述，例如“剑魔 Q 命中，造成 1234 伤害；敌方反击造成 890 伤害”。
- Q/W/E/R 技能卡提供悬停及键盘焦点说明层：技能名称、基础/攻击力伤害、命中率、持续回合、特殊状态和战术用途。说明文本以当前规则为准：Q 90% 命中并循环三段；W 70% 命中且削弱下一击；E 获得本回合护甲并持续三回合吸血；R 持续三回合提升攻击。
- 技能卡正文只显示技能键、名称和一个短标签；完整文本只在悬停或键盘焦点浮层显示，绝不占用四宫格卡片正文。完整文本使用本题实际结算规则的 LoL 风格描述，不使用泛泛教程文字。Q 浮层必须包含三段伤害 `200+150%攻击`、`350+220%攻击`、`600+400%攻击`、90% 命中及暗裔契约 Q3 效果；W/E/R 分别说明 70% 命中与下一击减攻、+100 护甲与三回合额外吸血、三回合 +25% 攻击。
- 属性面板新增“吸血：X%”。饮血剑每件提供 20% 吸血且可叠加；所有 Q/W 造成的实际伤害按面板吸血百分比回复生命。E 激活后的三回合在面板吸血之外额外提供 30% 吸血。治疗不得超过最大生命，并显示绿色治疗浮字。
- CTF 的批购与篝火检索接口保持可从源码/API 发现，但默认玩家界面不以 JSON 或调试控件形式暴露它们。

## 验收与自检

- 生成图第 2–24 层每层均有 4–6 个节点，仍无相邻层全连接且 Boss 可达。
- 页面存在 SVG 连线，连线数量与 `map.edges` 一致；仅可达节点可点击。
- 动态高层敌人显示的当前 HP 永远不超过总 HP。
- 失败或胜利后点击重新开始必定创建新 run；每个攻击回合可见双方对应的伤害/治疗浮字。
- 正常玩家能从地图、技能、商店、篝火和事件界面理解风险、收益、属性、失败原因及下一步操作，不需要阅读接口返回。
- 属性面板的吸血数值、伤害后的实际治疗、E 的额外吸血和技能浮层文字均与服务端同一套规则一致。
- 全量 pytest、JavaScript 语法检查与 Docker 自动求解器通过。
- 无待定项，未改变地图玩法、Boss 数值或 CTF 利用链。
